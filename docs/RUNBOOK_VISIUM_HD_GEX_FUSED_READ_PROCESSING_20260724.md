# Runbook: fused paired-read processing for Visium HD 3-prime GEX

Date: 2026-07-24

Branch: `feature/visium-hd-gex-fused-read-processing-20260724`

Base: STAR Suite `master` at `2deae6a`

## Objective

Replace the production-only external R1/R2 reconciliation pass with one
STAR-owned paired-read ingestion. STAR must consume each paired FASTQ record
once, map only R2, pass the already-paired raw R1 record to the optimized
Visium HD decoder, and combine the resulting coordinate candidates with the
modern post-rescue GeneFull evidence without reopening either FASTQ.

This is a scheduling and evidence-transport change. It must not change:

- the R1 candidate envelope or edit-distance scoring;
- the raw 9-nt UMI;
- GeneFull annotation, genomic-multimapper rescue, or decoy handling;
- candidate-specific `1MM_CR` UMI correction or `MultiGeneUMI_CR`;
- strict, soft-expected, hard, or gated-hard assignment semantics; or
- the 2, 8, and 16 micrometer materialized matrices.

The existing contracts workflow remains the independent parity oracle during
this tranche. It is not the intended full-slide production path after fused
parity is established.

## Scope of this tranche

The optimized R1 decoder is still maintained in the companion
`visium-hd-processing` repository. This tranche does not duplicate that large
implementation inside the STAR core. Instead, it changes ownership of the raw
read stream:

```text
                         one STAR FastxInputModule read
                                      |
                         paired {R2, raw R1} record
                              /                 \
             R2 GeneFull alignment          raw R1 stream tap
             and CR rescue in STAR              to decoder
                              \                 /
                       ordinal/name-validated merge
                                      |
                       normalized molecule evidence
                                      |
                    resolver -> policy materializer
```

The raw-R1 stream tap is an uncompressed FIFO written while STAR holds its
canonical input mutex. It therefore has exactly STAR input order and applies
backpressure rather than accumulating a full slide in memory. The companion
decoder consumes that stream directly. It does not open the source R1 FASTQs.

The fused join consumes the decoder's complete one-row-per-read decode table,
the candidate table, and the STAR sidecar. It validates the same blockwise
read-name digests generated by STAR, but it does not rescan R1 or R2. Candidate
read names, candidate counts, global ordinals, GeneFull records, H0 priors, and
the coordinate universe must all reconcile before normalized evidence is
committed.

This deliberately keeps a narrow process boundary around the decoder while
eliminating the expensive independent-input contract. A later tranche may
link the decoder as a STAR module after this evidence path is proven at full
slide scale; that is not required for 100K parity.

## Candidate and assignment contract

R1 decoding must retain every best-envelope coordinate candidate. Each row
continues to carry:

- `row2` and `col2`;
- BC1 and BC2 edit distance;
- BC1 and BC2 observed length;
- full-barcode start;
- minimum decode tier; and
- Phred-derived log sequence likelihood.

Candidate enumeration and assignment policy are orthogonal. A hard policy may
not prune candidate rows needed by soft-expected resolution. The fused driver
must support the existing policy names:

```text
strict
soft_expected
hard
gated_hard
all
```

The parity run uses `--assignment-policy all`. A production caller may instead
select `strict`, `soft_expected`, `hard`, or `gated_hard`; the wrapper passes
that choice to `molecule_first_materialize --products`. Policy selection happens
only after the complete candidate evidence and all resolver products have been
written, so it cannot prune the candidate universe or change gene resolution.

## Default-off and scRNA-seq isolation

The fused path is enabled only by an explicit Visium HD GEX option. With the
option absent:

- STAR opens no R1 tap;
- normal Fastx input buffers are unchanged;
- `readNmates`, Solo barcode parsing, CB/UMI correction, and cell calling are
  unchanged;
- no spatial sidecar or fused evidence file is written; and
- ordinary scRNA-seq and paired-end alignment commands reject spatial-only
  flags rather than partially enabling the path.

The fused mode inherits the existing fail-closed sidecar recipe: two FASTQ
ends ordered as R2 then raw R1, R2-only mapping, GeneFull, CR-compatible
multimapper rescue, no SAM/BAM carrier tags, no cell filtering, and no
two-pass/restart execution.

## Failure and completion contract

1. Create the FIFO in a fresh output directory.
2. Start the R1 decoder first; it may build its lookup tables before opening
   the FIFO.
3. Start STAR with the FIFO tap and the modern GeneFull sidecar.
4. STAR writes each raw R1 record exactly once in canonical paired-input order.
5. If either producer fails, terminate the sibling process group, suppress H0,
   join, resolution, materialization, and the completion marker.
6. Close and remove the FIFO after both producers exit.
7. Build H0 from the completed decoder statistics.
8. Run the fused join without any FASTQ arguments.
9. Write `RUN_COMPLETE.json` only after resolver determinism, matrix mass, and
   parity gates pass.

An incomplete FIFO, short decoder stream, extra decoder row, name-digest
mismatch, missing sidecar ordinal, malformed candidate group, or coordinate
outside the declared universe is fatal.

## Fixture-free gates

Required tracked tests must prove:

- the R1 tap is absent by default;
- invalid non-spatial uses fail before input is opened;
- tap records preserve input order, names, sequence, and qualities;
- a decoder failure terminates STAR and withholds the join;
- a STAR failure terminates the decoder and withholds the join;
- fused digest validation catches reordered, missing, and extra decode rows;
- candidate edit-distance and likelihood fields survive unchanged;
- strict, soft-expected, hard, and gated-hard consume the same candidate
  universe; and
- the existing sidecar-off scRNA-seq regression remains unchanged.

## Parity gates

Both runs must reconcile exactly 100,000 read pairs and 100,000 GeneFull
sidecar records. Compare byte size and SHA-256 for:

- raw R1 candidate rows;
- H0 prior rows;
- normalized evidence;
- strict, soft-expected, hard, and gated-hard resolver products; and
- all 36 MEX axis/matrix files across four policies and three spatial scales.

Logs, command manifests, elapsed times, and source paths are expected to differ.

The fused path is accepted only if every scheduling-independent product is
byte-identical, every invariant is true, the source worktrees are clean, and
the wrapper completion markers identify the exact commits. The 100K fixture is
a correctness test, not a speed benchmark. Full-slide performance must be
measured separately with enough workers to saturate the host and with a
declared warm/cold index-cache policy.

## Recovery after interruption

1. Confirm this branch and both source repositories are clean.
2. Clean-rebuild STAR before diagnosing any crash or parity failure.
3. Never reuse a partial output root or FIFO.
4. Treat only wrapper-written `RUN_COMPLETE.json` as completion.
5. Do not infer completion from STAR progress logs or process names.
6. Resume with fixture-free tests before launching either fresh 100K run.
